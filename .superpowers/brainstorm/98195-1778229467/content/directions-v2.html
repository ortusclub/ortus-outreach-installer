How interaction works

  1. 1Click "▶ Run" on a brief card → campaign starts immediately with all defaults. Card flips into a live progress card with a stop button. No wizard, no confirm dialog. (↵ on hover also fires it.)
  2. 2Click "Run all 3 in order" → queues all three jobs back-to-back. Sidebar gets a live timeline; each finishes and the next starts automatically. One press = whole day done.
  3. 3Click "Tweak" → card expands inline (no modal, no page change). Edit only the fields that differ from default — sheets, accounts, filters. Save & run fires it; Save only updates the brief and keeps the queue paused.
  4. Hover any card → reveals a one-line "why this is recommended" (e.g. "38 invites are 4+ days old"). Hover sticks for 2s before fading.
  5. Replies sidebar item → click to slide in a right pane with the latest 12 inbound replies, each with a "Mark as deal / Snooze / Reply manually" inline action.
  6. Recipes = saved tweaks. Anything you save under a name shows up tomorrow as a one-tap option ("Run Spring-UK Connect" instead of building it again).
Best forYou who already knows what should run; the app does the planning so you don't open the wizard at all most days.
The betMost outreach work is repetitive. The app is smarter than the form; it should propose the day, you approve.
Trade-offNeeds a "today's brief" computation (sheet sync + decay rules). Less control surface visible — power users may want a "show me everything" toggle.

How interaction works

  1. 1Press ⌘K (anywhere, any time) → palette opens, focus is in the input. This is the only "primary action" in the app. No "+ New Campaign" button anywhere.
  2. 2Click any board card → right pane slides in showing the live log, the sheet preview, and a Stop / Pause / Skip-this-account control. Esc closes it.
  3. 3Type in palette → live results: campaigns to run, saved recipes, history rows, account commands ("pause SC for today"), even sheet rows. Press ↵ to fire the highlighted action; press ⇥ to fill in defaults and edit them inline before firing.
  4. Top-result confirm: if you typed "connect spring" the top row already has full forecast — pressing ↵ is exactly the same as the old wizard's Launch button, in 1.2s instead of 5 sections.
  5. Drag a card on the board into "Queued" → it pauses; drag from "Queued" into "Running Now" → it starts. The board itself is a live control surface, not a read-only dashboard.
  6. Right-click any card → contextual menu: Stop · Pause · Save as recipe · View log · Open sheet.
Best forOperators who'd rather type than scroll. Linear / Raycast / Superhuman feel.
The betEvery action in Ortus is a verb-noun pair ("run connect on Spring-UK"). Express that as a search, not a form, and the wizard collapses to one keystroke.
Trade-offDiscoverability — new users won't know ⌘K exists. Mitigated with a one-time onboarding overlay. Mouse-only operators may resent it; the board cards keep the click path alive for them.

How interaction works

  1. 1Drag a chip from the left palette onto the recipe card → it snaps into the matching ingredient row (mode / sheet / accounts / template). The dotted outline fills in solid; forecast updates live at the bottom.
  2. Click any filled ingredient → swap it in place via a small popover (e.g. click "Spring-UK-Partners" → list of all sheets, pick a different one).
  3. Click × on an ingredient → removes it; the row goes back to dashed empty. Forecast greys out until refilled.
  4. 2⇧⌘S → name and save the recipe. Saved recipes show up in sidebar under "My recipes". Re-running is one click.
  5. 3"Schedule daily" → opens a tiny scheduler popover (every weekday at 9am; pick days). Recipe runs itself; brief view shows what was run.
  6. Drag a saved recipe onto the canvas → duplicates it as a starting point for a variant. Drag two recipes onto canvas at once → chains them (Connect → Check Status → Message).
  7. Right palette ("Fine-tune") only appears once core ingredients are filled — keeps the empty state calm. Throughput knobs live there as draggable chips, not exposed forms.
Best forTeams that run a fixed set of repeatable campaigns. Each campaign is a saved object you keep reusing.
The betThe wizard's real job is to build a thing. So make the thing tangible — a card with ingredients — instead of a form that produces no artifact.
Trade-offDrag-and-drop on desktop is fine but less obvious than a form for first-timers. Mitigated by also allowing click-to-add (chip → click → pops a destination picker).
