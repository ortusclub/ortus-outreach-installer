<objective>
Reduce RAM pressure and timeout failures on end-user machines (colleagues running on slow/overloaded hosts) by applying three coordinated, non-breaking edits. This is delivery hardening — no core outreach logic changes.

**Purpose:** End users hit `Runtime.callFunctionOn timed out` in real runs because single `page.evaluate()` calls took 70–90s on CPU-pinned hosts. We also saw retries firing back-to-back with only 5s gaps, which doesn't give the host time to recover. And we want an early warning when the host is already under load before we ever open a browser.

**Output:** Updated `src/gologin-launcher.js` (longer protocolTimeout + memory flags) and `src/campaign.js` (longer retry backoff + host-health preflight warning).
</objective>

       ```javascript
       /**
        * Host-resource preflight — non-blocking. Returns warnings if the host
        * is already under heavy load so the caller can surface them to the
        * operator before opening any browsers.
        */
       function checkHostHealth() {
         const warnings = [];
         const GB = 1024 * 1024 * 1024;
         const freeGB = os.freemem() / GB;
         const totalGB = os.totalmem() / GB;
         const load1 = os.loadavg()[0];
         const cpuCount = os.cpus().length;
         const loadThreshold = cpuCount * 0.8;

         if (freeGB < 2) {
           warnings.push(`Free RAM is ${freeGB.toFixed(1)}GB / ${totalGB.toFixed(1)}GB total — low.`);
         }
         if (load1 > loadThreshold) {
           warnings.push(`1-min load average ${load1.toFixed(2)} exceeds ${loadThreshold.toFixed(2)} (${cpuCount} CPUs × 0.8).`);
         }
         return { ok: warnings.length === 0, warnings };
       }
       ```
