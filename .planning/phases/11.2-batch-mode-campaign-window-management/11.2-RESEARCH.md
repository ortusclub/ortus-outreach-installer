**Researched:** 2026-04-22
**Domain:** Campaign orchestration refactor + macOS window/dock management + Electron tray mode

## Research Summary

Five focus areas, five concrete answers:

1. **macOS minimize** — Use `osascript` with `first process whose unix id is <PID>`. Orbita registers as its own macOS process (`CFBundleName=Orbita`, `CFBundleIdentifier=com.gologin.orbita`, bundle at `~/.gologin/browser/orbita-browser-<ver>/Orbita-Browser.app`) and `getProfilePid` already returns its top-level PID. `set miniaturized of every window to true` via System Events works on Chromium-derived apps. `set visible of process … to false` also works but "hides" (disappears from screen entirely) rather than minimizing to dock — we want minimize, per the CONTEXT "shows in dock but not on desktop" wording.
2. **Electron tray** — Standard pattern: create `Tray` in `app.whenReady()`, call `app.dock.hide()` on darwin, defer `BrowserWindow` creation until first tray click, override `window-all-closed` to NOT quit, override the window `close` event with `event.preventDefault(); win.hide()`. Electron 33 (already installed) supports all of this.
3. **Campaign loop refactor** — The minimal diff is: delete STEP 1 (lines 416-548), replace STEP 2 round-robin with a batch-of-5 loop that lazy-launches profiles on first batch. The `LEADS_PER_ROTATION=5` branch at 611-614 gets unified to always-5. The session-break at 915-919 is deleted; between-batch gap comes from `batches_per_hour`. Throttle/parking/retry/error paths are all inside the inner per-lead body and remain byte-identical.
4. **Rate & Limits UI** — The form ALREADY uses "Connections per account / hour" (`#rate-per-hour`) + "Max connections per account (total)" (`#daily-limit`). The CONTEXT's description of "daily-limit + gap min/max" is **outdated** — the v2.0 UI refactor already happened. What 11.2 does: relabel `#rate-per-hour` → "Batches per hour" (value range 1-6, default 2), clamp 1-30 → 1-6, keep `#daily-limit` as a backend safety cap (hide or relabel), and derive the per-lead within-batch gap from either a new pair of fields or a keep-current-style derivation. Most of the form-submit handler in `app.js:1318-1402` stays.
5. **Profile close/re-open cycle** — `GL.stop()` always does `stopAndCommit({posting: true})` which calls `commitProfile()` → uploads the profile zip to S3. That's the "Profile has been uploaded to S3 successfully" log line (at `gologin.js:228`) and is the cost. Re-opening invokes `spawnBrowser()` fresh (fetches profile zip, unpacks, launches Orbita). Empirically this takes **~10-30s** on a fast network (zip download + unpack). Login state IS preserved because cookies persist in the S3-committed profile zip. Net recommendation: close threshold of 15 minutes is sound — below that, the S3 round-trip cost dwarfs the RAM savings of closing.

**Primary recommendation:** Implement in this task order: (Task 1) `src/mac-window.js` helper module with `minimizeByPid(pid)` and `unminimizeAll()`; (Task 2) wire the minimize call into both launchers; (Task 3) campaign loop refactor — single large edit to `src/campaign.js` replacing STEP1/STEP2 blocks with a lazy-launch batch loop; (Task 4) Electron tray wiring in `electron/main.js`; (Task 5) UI relabel in `public/index.html` + minimal JS changes in `public/js/app.js`. Test coverage via a new `tests/batch-loop.test.js` + `tests/mac-window.test.js` (mocking `execFile`).

### Pattern 1: Minimize-by-PID via osascript

**What:** Send a precise AppleScript to a named PID, minimize all its windows, swallow errors.
**When to use:** After `GL.start()` returns success and we have `getProfilePid(profileId)`.
**Example:**

```javascript
// src/mac-window.js
// Source: AppleScript System Events — verified MacScripter thread + CONTEXT D-16.
import { execFile as execFileCb } from 'node:child_process';
import { promisify } from 'node:util';
const execFile = promisify(execFileCb);

const isDarwin = process.platform === 'darwin';

/**
 * Minimize every window of the process with the given unix PID.
 * Best-effort: swallow all errors, never block the caller.
 * No-op on non-darwin platforms.
 */
export async function minimizeByPid(pid) {
  if (!isDarwin || !pid) return;
  const script =
    `tell application "System Events" to ` +
    `set miniaturized of every window of (first process whose unix id is ${Number(pid)}) to true`;
  try {
    // 2s timeout — if AppleScript hangs, don't stall the campaign.
    await execFile('/usr/bin/osascript', ['-e', script], { timeout: 2000 });
  } catch {
    // best-effort, log nothing — CONTEXT D-16 "Failures are swallowed"
  }
}

/**
 * Un-minimize every window of every live browser PID.
 * Used by the dashboard "Show Browsers" debug button (D-18).
 */
export async function unminimizeByPids(pids) {
  if (!isDarwin) return;
  for (const pid of pids) {
    if (!pid) continue;
    const script =
      `tell application "System Events" to ` +
      `set miniaturized of every window of (first process whose unix id is ${Number(pid)}) to false`;
    try {
      await execFile('/usr/bin/osascript', ['-e', script], { timeout: 2000 });
    } catch { /* */ }
  }
}
```

Rationale for each choice:
- **`first process whose unix id is <N>`** — verified syntax, targets one process unambiguously. Multiple Orbita PIDs exist concurrently; name-based targeting would be ambiguous.
- **`miniaturized` not `visible`** — CONTEXT wants "minimized to dock", not "hidden from Cmd-Tab".
- **`execFile` not `exec`** — no shell injection surface (we interpolate `Number(pid)` after a numeric cast).
- **2s timeout** — AppleScript usually returns in <200ms; 2s catches a wedged System Events.
- **No logging** — best-effort; ambient log noise hurts more than it helps when this silently works 99% of the time.

### Pattern 2: Electron tray-first boot with lazy window

**What:** Tray lives for the whole app lifetime; BrowserWindow is created on demand.
**When to use:** macOS and cross-platform tray apps where the window is secondary to the background service.

```javascript
// electron/main.js — replaces the current createWindow flow
import { app, BrowserWindow, Tray, Menu, shell } from 'electron';

let tray = null;
let mainWindow = null;
const ICON_PATH = resolve(__dirname, '..', 'build', 'tray-iconTemplate@2x.png');

function getOrCreateWindow() {
  if (mainWindow && !mainWindow.isDestroyed()) {
    mainWindow.show();
    mainWindow.focus();
    return mainWindow;
  }
  mainWindow = new BrowserWindow({
    width: 1400, height: 900, minWidth: 1100, minHeight: 700,
    title: 'The Ortus Outreach',
    backgroundColor: '#0d1117',
    webPreferences: {
      preload: resolve(__dirname, 'preload.js'),
      contextIsolation: true, nodeIntegration: false, sandbox: true,
    },
    show: false,
  });
  mainWindow.once('ready-to-show', () => mainWindow.show());
  mainWindow.on('close', (e) => {
    // D-21: X hides to tray, does not quit.
    if (!app.isQuitting) {
      e.preventDefault();
      mainWindow.hide();
    }
  });
  mainWindow.webContents.setWindowOpenHandler(({ url }) => {
    if (url.startsWith('http')) { shell.openExternal(url); return { action: 'deny' }; }
    return { action: 'allow' };
  });
  mainWindow.loadURL(`http://127.0.0.1:${serverPort}/`);
  return mainWindow;
}

app.whenReady().then(async () => {
  try {
    await startServer();  // existing

    // D-19: hide dock FIRST so the icon never flashes into the dock
    if (process.platform === 'darwin' && app.dock?.hide) app.dock.hide();

    tray = new Tray(ICON_PATH);
    tray.setToolTip('The Ortus Outreach');

    const buildMenu = () => Menu.buildFromTemplate([
      { label: 'Show Dashboard',   click: () => getOrCreateWindow() },
      { label: 'Start Campaign…',  click: () => {
          const w = getOrCreateWindow();
          w.webContents.once('did-finish-load', () => w.webContents.executeJavaScript(
            "document.getElementById('nav-pace')?.scrollIntoView()"
          ));
      }},
      { label: 'Show Browsers',    click: () => fetch(`http://127.0.0.1:${serverPort}/api/browsers/show`, { method: 'POST' }) },
      { type: 'separator' },
      { label: 'Quit',             click: () => { app.isQuitting = true; app.quit(); } },
    ]);
    tray.setContextMenu(buildMenu());

    // macOS: left-click toggles dashboard. Windows/Linux: left-click shows context menu by default.
    tray.on('click', () => {
      if (mainWindow && mainWindow.isVisible()) mainWindow.hide();
      else getOrCreateWindow();
    });
  } catch (err) {
    dialog.showErrorBox('The Ortus Outreach', `Failed to start.\n\n${err.message}`);
    app.quit();
  }
});

// D-21: don't quit when all windows close — tray keeps us alive.
app.on('window-all-closed', (e) => {
  // Previously: if (process.platform !== 'darwin') app.quit();
  // Now: NEVER quit from window close on any platform; only tray-menu Quit or Cmd+Q quits.
  // Cmd+Q is handled by the default menu and sets app.isQuitting via before-quit:
});
app.on('before-quit', () => { app.isQuitting = true; });
```

Key event orderings (from Electron docs + confirmed patterns):
1. `app.dock.hide()` must be called AFTER `app.whenReady()` resolves. Called earlier it's a no-op because `app.dock` is not yet initialized.
2. `Tray` must be constructed after `whenReady` (the GPU/menu system needs to be up).
3. `mainWindow.on('close', …)` with `event.preventDefault()` is the standard hide-to-tray pattern. It is a true no-quit: `window-all-closed` does NOT fire when close is prevented.
4. The `app.isQuitting` flag is the standard escape hatch so `Cmd+Q` / tray-menu Quit actually closes the window and exits cleanly.
5. Tray icon file must end in `Template.png` (or `Template@2x.png`) on macOS for the OS to automatically invert colors for dark-mode compatibility. The current `build/icon.png` is full-color (113KB) — not suitable. We must generate a mono 22×22 + 44×44@2x template image.

### Pattern 3: Lazy-launch batch loop (control flow)

**What:** Replace STEP1 (open all upfront) + STEP2 (round-robin one lead each) with a single loop that opens a profile when its batch starts, processes 5 leads, then either parks or closes.
**When to use:** This phase. Core refactor.

```javascript
// Pseudocode for the new startCampaign body — replaces campaign.js:407-959 (STEP 1 + STEP 2 + STEP 3)

      // [performOutreach with retry loop — keep verbatim from :690-739]
```

### Anti-Patterns to Avoid

- **Shelling out via `exec` instead of `execFile`** — invites shell injection via profile name in any future osascript that references it. Use `execFile('/usr/bin/osascript', ['-e', script])` with integers cast via `Number()` for PIDs.
- **Calling `app.dock.hide()` before `app.whenReady()`** — silently no-ops. Always inside the `whenReady().then(…)` block.
- **Missing `app.isQuitting` flag on `Cmd+Q`** — without it, `window.on('close')` preventDefault blocks quit and the app becomes unkillable except via `kill -9`.
- **Targeting Orbita by name in AppleScript** — multiple instances exist. Always by `unix id`.
- **Triggering re-launch on every batch gap < 15min** — the S3 upload/download cycle is 10-30s each way; churn defeats the purpose.
- **Making batch size configurable in the form** — CONTEXT D-01: hard cap of 5 for v1. Don't expose it.
- **Calling osascript inside the critical path** — wrap with short timeout (2s) so a hung System Events doesn't stall a lead.

## Common Pitfalls

### Pitfall 1: AppleScript target-before-window-exists race

**What goes wrong:** `GL.start()` resolves when Orbita's DevTools endpoint is reachable — BEFORE the visible window has finished its first compositor frame. An osascript call fired immediately after may run against a process that has zero windows yet → `miniaturized of every window` is a no-op on the empty window list, and the window pops up on-screen a moment later.

**Why it happens:** Chromium window creation is async on the main thread; DevTools port binding happens first.

**How to avoid:** Either (a) add a 500ms delay before `minimizeByPid`, or (b) wrap the AppleScript in a repeat-until-window-exists loop inside the script itself. Option (b) is cleaner:

```applescript
tell application "System Events"
  repeat 10 times
    if (count of windows of (first process whose unix id is <PID>)) > 0 then exit repeat
    delay 0.1
  end repeat
  set miniaturized of every window of (first process whose unix id is <PID>) to true
end tell
```

Total added wall-clock worst-case: 1s. Typical: <300ms.

**Warning signs:** Operator reports "the browser flashed on-screen briefly before minimizing" — means we're firing too early.

### Pitfall 2: `window-all-closed` on Windows/Linux with tray mode

**What goes wrong:** Previous behavior (`if (process.platform !== 'darwin') app.quit()`) explicitly quit on non-macOS when all windows closed. With tray mode, we want NO quit on window close on any platform — the tray keeps the app alive. If we leave the old handler in, the first close on Windows/Linux exits the app and the tray icon disappears with it.

**Why it happens:** CONTEXT D-22 says "Windows/Linux same pattern; no `app.dock.hide()` equivalent needed." It does NOT remove the original `app.quit()` guard.

**How to avoid:** Delete the `process.platform !== 'darwin'` branch. Leave `window-all-closed` as a no-op. Only `before-quit` sets the flag; only `Cmd+Q` / tray Quit menu actually quits.

**Warning signs:** "Closing the dashboard makes the tray icon disappear."

### Pitfall 3: Calling `app.dock.hide()` when there's already a visible window

**What goes wrong:** On macOS, if a BrowserWindow was shown before `dock.hide()` is called, the dock icon may already be "sticky" and refuse to disappear until the app restarts. The current `main.js` creates the window BEFORE dock.hide() would fire.

**Why it happens:** Electron on macOS uses `LSUIElement` (Launch Services UI Element) semantics; this is toggled by `dock.hide()`/`dock.show()` but the toggle is cleanest when done before any NSWindow appears.

**How to avoid:** Boot order MUST be: `whenReady` → `startServer` → `app.dock.hide()` → `new Tray()`. No BrowserWindow creation happens until the first tray click.

**Warning signs:** "Dock icon won't go away even after I closed the window." Means the window was created before dock.hide().

### Pitfall 4: Tray icon at wrong size / not Template image

**What goes wrong:** Menubar icon renders as a full-color postage stamp instead of adapting to dark mode. Users on macOS dark mode see garish colors.

**Why it happens:** macOS only inverts icons whose filename ends in `Template.png` / `Template@2x.png`. The icon must be monochrome with transparency.

**How to avoid:** Export two PNGs: `build/tray-iconTemplate.png` (22×22) and `build/tray-iconTemplate@2x.png` (44×44), both mono on transparent background. Electron autoloads `@2x` when it finds it next to the base. Pass the base path to `new Tray(path)` — no `nativeImage` conversion needed on macOS when filenames follow the convention.

**Warning signs:** Operator screenshot shows a vividly-colored tray icon in dark menubar.

### Pitfall 5: S3 upload blocking the campaign

**What goes wrong:** `GL.stop()` blocks for 5-30s while it zips the profile and `POST`s to GoLogin's S3 gateway. If we close-between-batches for 3 profiles and all 3 close at once, we wait 30-90s before next batch can start.

**Why it happens:** `stopAndCommit` is the only public stop method; `posting: true` is hardcoded in `stop()` (`gologin.js:1464`). Even `stopLocal({posting: false})` (line 1467) still runs `sanitizeProfile` and `clearProfileFiles`.

**How to avoid:** (a) Only close ONE profile at a time — serialize close operations. The proposed loop already does this (the `for (profileId of activeProfiles)` is sequential). (b) Start closes in parallel with the between-batch wait, not blocking the next profile's batch: `closeSession(id).catch(() => {})` without await, then await only at the end of the campaign. (c) Set `PROFILE_CLOSE_GAP_MIN` conservatively (15+) so close cost amortizes over the idle period.

**Warning signs:** Logs show "Profile has been uploaded to S3" immediately followed by "▶ Opening X" for another profile with a 30+s gap.

### Pitfall 6: Orbita processSpawned is the bash wrapper, not the real Chromium

**What goes wrong:** On some historical GoLogin SDK versions, `GL.processSpawned.pid` returned the shell wrapper PID that spawned Orbita, not Orbita itself. Targeting that PID in osascript finds a non-Cocoa process with no windows → no-op.

**Why it happens:** `gologin.js` branches on `this.vnc_port`: if set, uses `execFile(script_path, [...])` with a bash wrapper. If not set, uses `execFile(ORBITA_BROWSER, params, {env})` directly.

**How to avoid:** Verified: in our config (`vnc_port` unset, we never set it), GoLogin takes the direct path (`gologin.js:1017` `execFile(ORBITA_BROWSER, …)`). `processSpawned.pid` IS the Orbita PID. Phase 11.1 already relies on this and `getProfilePid` works for `pidusage` sampling. No action needed.

**Warning signs:** `ps -p <pid> -o comm=` returns `/bin/bash` or similar instead of `Orbita`.

## Code Examples

### Example 1: The minimize helper end-to-end

```javascript
// src/mac-window.js
import { execFile as execFileCb } from 'node:child_process';
import { promisify } from 'node:util';
const execFile = promisify(execFileCb);

const isDarwin = process.platform === 'darwin';

export async function minimizeByPid(pid) {
  if (!isDarwin || !pid) return;
  const n = Number(pid);
  if (!Number.isFinite(n)) return;
  const script = `
    tell application "System Events"
      repeat 10 times
        if (count of windows of (first process whose unix id is ${n})) > 0 then exit repeat
        delay 0.1
      end repeat
      set miniaturized of every window of (first process whose unix id is ${n}) to true
    end tell
  `.trim();
  try {
    await execFile('/usr/bin/osascript', ['-e', script], { timeout: 3000 });
  } catch { /* best-effort */ }
}

export async function unminimizeByPids(pids) {
  if (!isDarwin) return { minimized: 0, skipped: 0 };
  let minimized = 0, skipped = 0;
  for (const pid of pids) {
    const n = Number(pid);
    if (!Number.isFinite(n)) { skipped++; continue; }
    const script =
      `tell application "System Events" to ` +
      `set miniaturized of every window of (first process whose unix id is ${n}) to false`;
    try {
      await execFile('/usr/bin/osascript', ['-e', script], { timeout: 2000 });
      minimized++;
    } catch { skipped++; }
  }
  return { minimized, skipped };
}
```

## Open Questions

1. **Should `dailyLimit` still be visible in the form?**
   - What we know: CONTEXT D-08 says "Daily cap becomes implicit" — computed from batches_per_hour × 5 × active_hours. Backend still uses `dailyLimit=40` as safety ceiling.
   - What's unclear: Does the operator need to tune it, or is a fixed 40 enough? If an operator runs 6 batches/hr for 10 hours, that's 300 leads — they'd hit the 40 cap at hour 1.3, which is probably the intent.
   - Recommendation: hide the `#daily-limit` field from the form (or relabel as "Safety cap (default 40)"), still save `dailyLimit=40` in the POST body so the backend sees it. Keep input in DOM for preset back-compat.

2. **Should the within-batch gap (delayMin/delayMax) be operator-configurable or derived?**
   - What we know: D-02 says "keep delayMin..delayMax, renamed 'Gap between leads within a batch'". The current form derives `delayMin/delayMax` from the `rate-per-hour` stepper.
   - What's unclear: Do we add explicit min/max steppers, or keep the derivation from a renamed "Gap per lead" single field?
   - Recommendation: add two simple steppers for min/max seconds (default 15/45), delete the derivation code at `app.js:1355-1369`. Simpler code, matches D-07 wording precisely.

3. **"Show Browsers" button: where does it live and how does it call the server?**
   - What we know: D-18 says dashboard button; CONTEXT `code_context.Reusable Assets` references `getActiveBrowserPids()` (already exists).
   - What's unclear: IPC path. Options: (a) new server endpoint `POST /api/browsers/show` that calls `unminimizeByPids(getActiveBrowserPids())`; (b) Electron preload exposes `window.ortus.showBrowsers()` that IPCs to main.
   - Recommendation: (a) server endpoint. Simpler, one code path, works identically in-browser and Electron.

4. **Tray icon template image — do we have a mono Ortus asset ready?**
   - What we know: `build/icon.png` is full-color (113KB).
   - What's unclear: whether a mono variant exists or needs to be produced.
   - Recommendation: plan includes a user-confirmation step or a scripted conversion (`sips -s format png` + ImageMagick `-colorspace Gray -alpha on`) as a fallback. If design-approved mono exists, use it.

5. **What's the abort latency during a between-batch wait if it's 25 minutes?**
   - What we know: existing sleep chunk pattern uses 2s slices so abort is responsive.
   - What's unclear: if we close the browser at the 15-min-gap threshold, the next abort-check inside `closeSession`'s `GL.stop` is tied to SDK internals.
   - Recommendation: keep the 2s chunked sleep pattern; don't try to abort mid-close (GL.stop is short enough on its own).
