## Decisions Made

- **`ensureOpen` + `closeSession` as closures inside `startCampaign`** rather than module-level helpers. They need `token`, `profileNameCache`, and the `sessions` Map — all of which are local to the campaign run. Promoting them to module-level would require threading state through parameters, obscuring the simple per-run semantics.
- **`getCloseGapMin()` reads env on every call** (not cached at module load) — allows operators to hot-edit `.env` between campaigns without restart. Matches the existing `rmCfg.IDLE_PARKING_ENABLED` pattern.
- **Labeled outer `outer: while` + `break outer`** chosen over a shared `leadsExhausted` flag alone. The flag is still the primary signal (needed for the `if (!row)` path inside the innermost for-loop), but the label ensures a clean exit from deep nesting without relying on the intermediate for-loops to also check `leadsExhausted` on every iteration. Both mechanisms coexist: flag catches exhaustion during lead search, labeled break gets us out cleanly from any depth.
- **Chunked 2s between-batch sleep AFTER the close decision** so wall-clock close latency (S3 upload round-trip) counts against the gap, not idle time. This keeps `batchesPerHour` semantically accurate when closes happen: 2 bph with a 30s close still sleeps only ~29.5 min afterwards, not 30 min on top.
- **`performOutreach` is called exactly once per lead** (confirmed via `grep "result = await performOutreach"` → 1 match). The import, the JSDoc on `parkProfile`, and a `// performOutreach with retry` comment round out the 4 total file occurrences — same as pre-refactor baseline.
