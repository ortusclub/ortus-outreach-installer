## Finding 2 — Auth headers (HIGH confidence)

Copy `getVoyagerDegree`'s header set from `src/linkedin/helpers.js:128-137`:

```javascript
{
  'accept': 'application/vnd.linkedin.normalized+json+2.1',
  'csrf-token': extractCsrfFromJsessionId(),
  'x-restli-protocol-version': '2.0.0',
}
// plus credentials: 'include'
```

Where `extractCsrfFromJsessionId()` is:
```javascript
const jsession = document.cookie.split(';').find(c => c.trim().startsWith('JSESSIONID='));
const token = jsession.split('=')[1]?.replace(/"/g, '');
```

This pattern already works in production for `getVoyagerDegree` (11.1 baseline commit `02e88cf`). Near-zero risk of it not working for the messaging endpoint — LinkedIn uses the same CSRF scheme across Voyager.

## Finding 3 — Pagination stop condition (HIGH confidence)

Voyager messaging responses are sorted by `lastActivityAt DESC`. Once we see a conversation with `lastActivityAt <= last_check_at`, we can stop paginating — all subsequent pages are older.

```javascript
async function fetchNewConversations(page, watermark) {
  const pages = [];
  let start = 0;
  while (true) {
    const batch = await getConversationsPage(page, { start, count: 20 });
    if (!batch.elements.length) break;
    pages.push(batch);
    const oldestInBatch = Math.min(...batch.elements.map(e => e.lastActivityAt));
    if (oldestInBatch <= watermark) break;  // ← stop here
    if (!batch.paging.total || start + batch.paging.count >= batch.paging.total) break;
    start += batch.paging.count;
  }
  return pages.flatMap(p => p.elements).filter(e => e.lastActivityAt > watermark);
}
```

Volume per profile expected to be low (< 5 pages = < 100 conversations scanned).

## Finding 4 — Name collision (MEDIUM confidence, decision here)

**Scenario:** Operator's sheet has two rows named "John Smith" messaged from the same account. LinkedIn returns one conversation with "John Smith" participant. Which sheet row gets the reply?

**Decision (per CONTEXT.md <open_questions>):** log + skip + surface "? ambiguous" row in the panel so operator sees it and can manually disambiguate.

**Implementation:**
```javascript
function matchConversationToSheet(conv, candidateRows) {
  const fullName = `${conv.participant.firstName} ${conv.participant.lastName}`.toLowerCase().trim();
  const matches = candidateRows.filter(r => 
    `${r.firstName} ${r.lastName}`.toLowerCase().trim() === fullName
  );
  if (matches.length === 0) return { match: null, reason: 'unmatched' };
  if (matches.length > 1) return { match: null, reason: 'ambiguous', candidates: matches };
  return { match: matches[0] };
}
```

Ambiguous rows render in the Replies panel with a `⚠ Ambiguous — multiple sheet rows match "John Smith"` marker. Sheet is NOT written for ambiguous matches (operator must disambiguate first).
