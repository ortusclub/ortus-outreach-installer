  <action>
**Per D-01, D-02, D-03:** Add HTTP Basic Authentication as an inline Express middleware in server.js.

1. After the `app.use(express.json());` line and BEFORE `app.use(express.static('public'));`, insert the auth middleware:

```javascript
// ── Basic Auth (D-01, D-02) ────────────────────────────────────────
app.use((req, res, next) => {
  const auth = req.headers.authorization;
  if (!auth || !auth.startsWith('Basic ')) {
    res.set('WWW-Authenticate', 'Basic realm="Ortus Dashboard"');
    return res.status(401).send('Authentication required');
  }
  const [user, pass] = Buffer.from(auth.split(' ')[1], 'base64').toString().split(':');
  if (user === process.env.DASHBOARD_USER && pass === process.env.DASHBOARD_PASS) {
    return next();
  }
  res.set('WWW-Authenticate', 'Basic realm="Ortus Dashboard"');
  return res.status(401).send('Invalid credentials');
});
```

2. This middleware runs before `express.static('public')` AND before all `/api/*` routes, so per D-02, both dashboard HTML pages and API endpoints are protected.

3. Per D-03, no session management or login page is needed -- the browser-native Basic Auth prompt handles credential entry.

4. Do NOT use any external auth library -- hand-roll the Basic Auth parsing as shown above. The logic is 10 lines; a library would be overkill for this internal tool.

5. Do NOT move express.static or any route handlers. Only insert the middleware block in the correct position.

**No other files are modified.** The DASHBOARD_USER and DASHBOARD_PASS env vars were already added to .env.example and validated at startup by Plan 01.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Express | Untrusted HTTP requests from any client |
| Authorization header -> credential check | Base64-decoded credentials compared to env vars |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05 | Spoofing | Auth middleware | mitigate | Require valid Basic Auth credentials on every request; reject with 401 |
| T-07-06 | Information Disclosure | Auth middleware | mitigate | Do not echo back credentials or env var values in error responses; generic "Invalid credentials" message |
| T-07-07 | Elevation of Privilege | Route ordering | mitigate | Auth middleware placed BEFORE express.static and all route handlers -- no bypass path |
| T-07-08 | Tampering | Basic Auth transport | accept | Credentials sent in cleartext over HTTP. Acceptable for internal/localhost tool. If deployed publicly, HTTPS would be needed (out of scope per D-08). |
| T-07-09 | Repudiation | Auth middleware | accept | No audit logging of auth attempts. Acceptable for internal single-operator tool. |
</threat_model>
