Chips Overhaul
Fleet status taxonomy · 4 variants · pick one
A
Lifecycle only · reason as text
One pill per row, only carries the state (Queued / Sending / Stopped). Any reason (limit hit, login needed, batch done) is plain text in the detail column. Cleanest visual, but "Stopped" alone doesn't tell you if action is needed.
1 LOUISA.VILLARIZA@ORTUS.SOLUTIONS Sending 18 / 50 · 2m ago
2 HANNAH.SAMSON@ORTUS.SOLUTIONS Queued
3 ABI.AGUSTIN@ORTUS.SOLUTIONS Stopped LinkedIn weekly cap (~100/wk)
4 LHUZ.D@ORTUS.SOLUTIONS Stopped Needs login
5 ANKIT.RATHOR@ORTUS.SOLUTIONS Stopped Batch complete · 50/50
Strength: visually quietest · matches existing layout exactly · easy to ship    Weakness: "Stopped" is overloaded — operator must read detail to know if action is needed
B
Two pills · status + reason · amber accent on action
Status pill stays neutral. A second reason pill carries the only non-neutral color (amber) when operator action is needed. Easier to scan a long fleet for "what needs me" at a glance.
1 LOUISA.VILLARIZA@ORTUS.SOLUTIONS Sending 18 / 50
2 HANNAH.SAMSON@ORTUS.SOLUTIONS Queued
3 ABI.AGUSTIN@ORTUS.SOLUTIONS Done LinkedIn weekly cap
4 LHUZ.D@ORTUS.SOLUTIONS Action Needs login
5 ANKIT.RATHOR@ORTUS.SOLUTIONS Done Batch · 50 / 50
Strength: "needs me" jumps out (the only amber row) · scales to many accounts    Weakness: two pills per row is more visual noise · slight tension with monochrome rule
C
Reason-first · the chip IS the message
No abstract state words. The chip says exactly what happened or what to do — "Sending 18/50", "LinkedIn weekly cap", "Needs login". No glossary needed. Chips vary in width which makes the fleet look slightly less grid-like, but nothing is ambiguous.

4 LHUZ.D@ORTUS.SOLUTIONS Needs login Session expired
5 ANKIT.RATHOR@ORTUS.SOLUTIONS Batch complete · 50 / 50 Resumes next run
Strength: zero translation — the chip explains itself · best for boss reading it cold    Weakness: chip widths vary · longer chips mean less room for detail column
D
Callout lane · "needs you" pulled above the fleet
Rows go back to simple lifecycle chips. Anything actionable — login needed, rate limit page hit, captcha — is hoisted into a dedicated callout strip above the fleet. The boss never has to scan all 5 rows to find what's blocking him; the alert finds him.

?
Legend behind a help icon · same on every variant
Small ? icon next to the "ACCOUNT QUEUE" label in the main UI. Hover/click opens this card. Same content regardless of which chip system we ship — it's just the glossary.
?
Account status — what each label means
Queued Waiting its turn — will run when an earlier account finishes.
Sending Currently sending connection requests / messages.
Batch done Account finished its target for this run (e.g. 50 / 50). Resumes next run.
LinkedIn cap LinkedIn imposed a limit (weekly invites, InMail credits). Won't resume until LinkedIn lifts it.
Action You need to do something — usually log into the GoLogin browser or solve a CAPTCHA.
Parked Account taken out of rotation mid-run (too many skips, rate-limit page). "Try again" to put back.
