Today, pressing BULK CHECK CONNECTIONS dumps multi-line log text into the italic span next to the button, while the main log panel below stays empty for those lines. The shared requirement across all variants: all bulk-check log lines also flow into the main #log-panel (with a "📡 Bulk check" marker so they're scannable). The four variants below differ only in what — if anything — sits next to the button itself.

Variant A Quiet pill — running indicator only

Inline area shows a single discreet line: spinner + "Sweeping 5 accounts…". No counts, no per-line text. Operator looks at the main log for detail. Cleanest, lowest-effort. Button itself disabled while running. Trivial to build — uses existing setStatus() with one short string. No progress signal at a glance; the operator has to read the log to know "are we 2 of 5 or 4 of 5?".

Variant B Determinate progress bar

Thin monochrome bar fills as accounts complete. Tabular "3 / 5" counter. We can derive this from the existing log stream (each [name] Launching browser… = account started; each 📡 with a profile name in a "done" line = account completed). Real progress at a glance. Sweeps that quietly hang on one account become visible because the bar stops moving. Requires a small parser to map log lines → "this account is done". Per-account counters can drift if the log format changes; needs a test.

Variant C Per-account ticker (boarding-pass style)

A short list materialises next to the button — one row per selected account, each with a dot (idle/active/done) and the account email. Most informative variant. Best when the operator wants to see "which account is the slow one". Per-account visibility — instantly shows which account is stuck or failed. Names are already known at click-time (selectedProfileIds + profiles map). Takes the most vertical space — 5 accounts ≈ 90px tall. Could feel cluttered on the live status pane during an active campaign. Hidden behind a disclosure?
