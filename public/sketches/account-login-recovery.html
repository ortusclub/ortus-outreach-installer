What this proposal means

  • “Running with 2 of 5 accounts” means two accounts remain eligible—not that two browsers necessarily run at once.
  • Keep eligible work moving under the existing queue and sender-assignment rules. Do not move account-bound conversations to another sender.
  • Login, security verification, weekly limits, rate limits and unknown failures get different explanations. A generic error is not proof of logout.
  • For VM profiles, the current safe route requires stopping the VM campaign and confirming closure before manual login. Per-account release would be additional backend work.
  • Automatic follow-ups must show the actual executing browser. A VM campaign’s personal follow-ups may run on this Mac; five independent sender rows only fit tasks that really have five executing accounts.
  • Proposed sender recovery: check login and identity first, then explicitly return that account to eligible work. This is not implemented here. Existing follow-up scheduling may resume eligible tasks after sign-in.
