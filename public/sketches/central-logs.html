Central Logs · Two Sheets, Two Apps Scripts

Two brand-new Google Sheets, each with its own dedicated Apps Script deployment. The campaign master sheet is left untouched.

Sheet 1 — Ortus Operations Log: per-campaign diagnostics. One tab per campaign run. Each tab holds every operation + error for that run. A custom menu in the sheet provides a one-click "Delete all log tabs" action so the operator can clear stale runs without manual right-click.

Sheet 2 — Ortus Campaign Activity: one sheet, one tab, one row per completed campaign. Per-operator summary band at the top. Cross-campaign analytics (how many campaigns each operator ran, how many leads each is reaching).

Bot's .env grows by two URLs: OPS_LOG_WEBAPP_URL + CAMPAIGN_LOG_WEBAPP_URL. Each Apps Script is container-bound to its own sheet — no openById needed.

Sheet 1 of 2

Ortus Operations Log · tab per campaign

Each new campaign creates a new tab. Tab name: {campaign-name} · {YYYY-MM-DD HH:mm}. Inside the tab, one row per event with severity-tinted rows. When the operator is done with old runs they hit the custom menu → "Delete all log tabs" and the sheet resets to just the "Index" tab. Custom menu — the Apps Script's onOpen trigger registers an "Ortus Logs" menu in the sheet's top bar. Operator clicks it → "Delete all log tabs" → confirmation dialog → all per-campaign tabs deleted. Index tab survives.

# Question
Q1 Resumed campaigns — new tab or append? When an operator hits "Resume" on a stopped CC+IC campaign, does it:
(a) Append rows to the original campaign's tab (one tab = one campaign name, all sessions).
(b) Open a new tab named {name} · {start} (resumed). Cleaner per-session telemetry, more tabs to manage.
(a) is more readable as "the story of this campaign"; (b) is more accurate as "what happened in this session."
Q2 Operations Log write cadence. Writing to the Apps Script web app costs ~500-1500ms per call.
(a) Per-event — every operation/error POSTs immediately. Real-time visibility, ~1s lag per row stamp.
(b) Batched (30s) — bot buffers events, flushes every 30s and at campaign end. Imperceptible per-event latency, errors visible within ~30s.
For diagnostic use (b) is enough. (a) only matters if you'd watch the sheet live to catch something mid-run.
Q3 Privacy on Campaign Activity templates column. Showing the full template body means every operator can read every other's connection notes verbatim.
(a) Full body in the cell (operators see each other's copy — useful for "what's working?").
(b) First 60 chars + "…" (recognise it, can't reuse it).
(c) Template name only (e.g., "Connection note · v3"). Requires operators to name templates first.
Q4 What does the Index tab show? One row per per-campaign tab in the Operations Log. Suggested columns: Tab name · Started · Operator · Total events · Errors · Warnings · Link (clickable jump to the tab). Confirm — or strip it down.
Q5 "Delete all log tabs" — guard rails. Anyone with edit access on the sheet can fire the menu item.
(a) Just the confirmation dialog (shown above).
(b) Dialog + require typing the word DELETE to confirm (extra friction).
(c) Restrict to the deploying account only — Apps Script's Session.getActiveUser() check. Other operators see "Only the script owner can delete tabs."
