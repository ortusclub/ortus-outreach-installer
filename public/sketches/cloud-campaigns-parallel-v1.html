Sketch — Cloud Campaigns, multiple parallel runs. Every cloud campaign renders as the same live-status card as a local run (real vj-card, real CSS) — a literal transposition. Because the cloud engine runs several campaigns at once, the singleton local card becomes a stack, bucketed into Active → Queued → Past. Each active card carries the full live log, per-account state, progress, batch settings and an added View campaign button. The old plain text strip and the dead "UNNAMED / 0-of-0" ghost card are retired.

How the lifecycle moves. A cloud campaign starts in Active (up to N run slots — the "run slots" dial from the concurrency sketch). Extra launches wait in Queued and auto-promote the instant a slot frees (pause / stop / finish all free a slot — no more "you have to stop it for the next to start"). When a campaign finishes or is cancelled it drops to Past with its final counts. The live log inside each active card is the same log you'd see running locally — it just needs the engine to expose per-lead events (the one piece that goes to Steven).
