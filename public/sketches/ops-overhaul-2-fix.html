Why it froze (confirmed from ops-log-bridge.js)

DESIGN

One tab per campaign

appendEvents calls insertSheet() for every new run — each tab pre-formats 1000 rows of conditional formatting (~26k cells).→

SCALE

The team runs many/day

joshua, jeremiah, reign, jhan, miggy, joaquin… plus reruns. Tabs pile up for weeks — nothing prunes them automatically.

→

CEILING

10M-cell limit hit

~380 tabs × 26k cells ≈ Google's hard cap. insertSheet / setValues starts throwing on 2026-06-10 06:36Z.→

SILENCE

Failure swallowed

flushOpsLog gets the error envelope, re-queues, and never warns. Buffer dies on the next app relaunch. 33h dark, unnoticed.

Campaign Activity never broke because it's a single append-only tab — no insertSheet, no cell explosion. That's the blueprint for the redesign below.

The fix, in three layers

1

Unblock now — no code, no release do today · ~30 seconds

The bridge already ships an operator menu for exactly this. Open “OPS AND LOGS — ORTUS OUTREACH — DO NOT DELETE” → menu Ortus Logs → Delete all log tabs. It removes every per-campaign tab (keeps Index), frees the cells, and appendEvents starts writing again immediately.

2

Durability — never silently lose events again small app change

  • Flush on shutdown. gracefulShutdown (SIGINT/SIGTERM) and the Electron quit path call flushOpsLog() before exit — so our pkill+relaunch cycle and operator quits stop dropping the buffered 0–30s of events.
  • Stop swallowing failures. When a flush keeps failing for > N minutes, surface it: a desktop notification + a line in the in-app log (“Operations Log not writing — check the sheet”). A 33-hour blackout should be impossible to miss.
  • Files touched: log-writer.js, server.js, electron/main.js — none off-limits. Unit-tested via the existing _setFetchImpl / _peekBufferForTest seams.
3

Redesign the log so it can’t overflow — and answers “who did it” in one glance bridge change + redeploy

Replace “one tab per campaign” with a single append-only Events tab. Same row fields you already send — just one growing table you can filter and pivot. Two variants:
