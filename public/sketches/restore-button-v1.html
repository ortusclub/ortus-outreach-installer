⚠ Recovery action

Force-restart the campaign engine?

Use this when something is stuck and Stop / Pause aren't responding. Below is exactly what happens. Your progress on already-processed leads is safe — Restore reads the same on-disk ledger any campaign would.

Kill Every running Orbita / Chromium / local-browser process (SIGKILL fallback after 2 s)
Reset All in-memory campaign state — counters, parked profiles, soft warnings, queue cursors
Preserve The on-disk ledger of which leads were already processed (state.json)
Restart The same campaign, seeded with today's per-account counts (Louisa picks up at 22/50, not 0/50)
In-flight toast
Shows for ~5 s during the restart
The restart sequence takes 3–8 seconds (kill processes, wait for browser teardown, re-seed counts, relaunch first profile). A toast keeps the operator informed and prevents them from clicking Restore again.

What it does (per state)
Behaviour map
Same button, three different end-states based on what was there to recover.
If a campaign is running → Force-kill everything, reset in-memory state, immediately restart with the same settings. Picks up at the next unprocessed lead. Used when the loop is wedged.
If the last campaign is stopped → Force-kill any orphan browsers, then act like Resume — relaunch with the settings of the last entry in history.json. Useful if a Stop left things half-torn-down.
If truly idle (no campaign anywhere) → Force-kill any orphan browsers, clear any stale lock files, show "Engine restored — nothing to resume." toast. The cleanup pass alone is useful (orphan Orbita windows after a hard quit, etc.).
