The sheet-write fallback, visually

When a row write to the Apps Script times out, the bot no longer gives up after one try. It retries idempotent writes a few times with a growing pause — so a one-off Google latency spike (like Kyra's) self-heals instead of leaving a blank row.

01Before vs after

Same event — one write hits a 15-second timeout. Old code dropped the row; new code recovers it.

After · v2.59.3

timeout — transient? yes
wait 1s · attempt 2
Apps Script responds 200 OK
✓ Kyra’s row written — recovered

If attempt 2 also timed out, it would wait 2s and try a 3rd time. After 3 failed attempts it finally gives up and logs — but the connection itself was still sent, only the sheet stamp is missing.

03The decision: retry vs don’t

Not every failure is worth retrying. Only transient (timeout/network) errors retry — permanent ones stop instantly so we don’t waste 30 seconds on a hopeless write.
