One job status, four jobs

Every slow thing in this app — a campaign sending, a bulk check sweeping, Follower Growth inviting, Magellan collecting or checking or importing — answers the same four questions: is it running, how far along, what is it doing right now, and how did it end.

Today each screen answers those from its own numbers, which is why one said 92% while another said 83%, and why a finished Check left "NOT RUNNING · 92% · 0 people". The proposal: the server keeps one job record, the card only draws it, and no component is allowed to compute a status of its own.

The record every job publishes
{ state: 'idle' | 'running' | 'done' | 'failed' | 'stopped', // the ONLY source of "is it running" title: 'Checking against HubSpot', // what this job is, in the operator's words step: 'Asking HubSpot who it already has', item: 'nushe.himaj@ortus.solutions', // what it is on right now done: 4, total: 13, unit: 'accounts', // coarse progress within: { done: 2300, total: 5945, unit: 'people' }, // progress inside the current item headline: { n: 18400, label: 'people checked' }, // the number worth watching stats: [ { n: 9623, label: 'new' }, { n: 15545, label: 'already there' } ], outcome: { ok: true, summary: '9,623 new · 15,545 already there · 3,727 duplicates', problems: 1 }, // set ONCE, when it ends. Never cleared by a redraw. }

Percentage is computed in one place from done/total and within. Nothing else may calculate one. state flips to done only after the job has written its outcome — which is exactly the bug that produced "NOT RUNNING, 92%, 0 people so far".

A job that ends must say what happened. Leaving live counters on screen is what makes a finished run look broken, and it is the same fix for all four cards.
