What each column means
Stage column D

The workflow state of the lead. This is what the bot reads to decide whether to process each row, and what it writes back after an action. It's the single source of truth for "where is this lead in the funnel."

Connect Pending — invite sent, waiting for accept
Connected · DM Now — accepted, ready for follow-up DM
Skipped — bot couldn't process (URL invalid, profile gone, etc.)
DM Sent / IC Sent / OP Sent / InM Sent — done
(blank) — never touched, eligible for connect campaign
Status column F (renamed → Connection Request Status)

An action-level marker the bot stamps after each operation. Tells the operator what the bot did on the last action. Less important than Stage — mostly informational.

Skipped — action couldn't be performed

4. Questions to send Sam before deploying

Issue #1 — Data loss on Date Last Action

  • My sheet has a single combined Date Last Action column (values like "May 6th, 09:56"), not separate Date + Time columns. Your COLUMN_RENAMES handles the latter but not the former — OLD_COLUMNS_TO_REMOVE deletes Date Last Action without migration. Every existing date stamp would be wiped. Can you add a split-migration step? (The underlying cell values are real Date objects so Apps Script can format them.)

Issue #2 — Connected Status loses its coloring

  • applyCCFormatting still looks for the "CC" header but the migration renames the column to "Connected Status". After deploy, the green / yellow / red conditional formatting silently no-ops on the renamed column. The catch-all "any non-blank = yellow invite pending" rule also goes away. Worth updating the function to read the new header (or both).

Issue #3 — Missing entries in MODE_TRACKING_COLUMNS

  • introduce_back and post_amplification aren't in MODE_TRACKING_COLUMNS. Both fall back to the full TRACKING_COLUMNS list, so an introduce_back run on a fresh sheet adds unused InMail / OP / Reply columns. Worth adding mode-specific entries — message_only's subset would suit introduce_back; post_amplification probably shouldn't write to the sheet at all.

Issue #4 — Probable typo in COLUMN_RENAMES

  • { from: 'Connected', to: 'Connected' } looks like a typo — probably meant Connected Already → Connected to migrate the legacy column? As written it's an idempotent no-op.
